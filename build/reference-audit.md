# 표·그림·조문 참조 전수 점검

2026-11-10. 원문 내용과 적용 연혁은 바꾸지 않고 참조 표시·원문 열람을 점검했다.

## 범위

- 실제 검색 카드 2,461개: 엘리베이터 881, 에스컬레이터 327, 표준화 816, 불합격 437.
- 적용 연혁이 있는 카드 1,002개. 모든 카드/연혁을 렌더링해 본문 보존, 중첩 버튼 없음, 연결 대상 존재를 검사한다. 브라우저 테스트의 카드 2,463개에는 경계 조건용 가상 카드 2개가 포함된다.
- 기존 카드·연혁이 참조하는 이미지 파일 680개: 실파일·크기·디코딩을 확인한다.
- 현행 표·그림 121개: 엘리베이터 표 29/그림 57, 에스컬레이터 표 14/그림 21. 중복 번호는 서로 다른 원본으로 센다.
- 현행 본문/제목에서 표제·이미지 내부 글자를 제외한 명시적 참조 219곳: 내부 참조 210곳 모두 연결. 나머지 9곳은 다른 별표 또는 KS 규격 인용이다.
- 전체 원문 열람 대상 175개: 현행 121개, 적용 연혁 25개, 표준화 자체 자료 29개. 모든 대상의 팝업과 모든 이미지 로딩을 휴대폰 폭에서 검사한다.
- 표준화 48개 안건의 참조를 연결하고, 적용 연혁 57개 블록의 참조를 당시 자료로 연결했다. 표준화는 번호와 인용 문구가 일치하는 자료, 또는 직접 확인한 해당 안건의 이미지로 연결한다.

## 수정

- 양쪽 기준의 표·그림을 같은 화면의 이동 가능한 참조 창으로 연다. `그림 1 및 2`처럼 뒤에 종류명이 생략된 번호도 처리한다.
- `표 Ⅱ.1의 3.1 및 3.6`, `표 Ⅻ.1(3.6)`의 번호는 표 항목이다. 일반 조문/정의로 연결하지 않고 해당 표를 연다.
- 긴 표의 모든 쪽을 포함한다. 엘 부속서 XⅢ 표 XⅢ.7의 첫 부분(369쪽)은 기존 파서에서 글자로만 남았으므로 원문 표 영역을 추가했다. 표 Ⅻ.1은 359~363쪽, 에스 표 8은 89~90쪽, 표 11은 120~122쪽 전체를 연결한다.
- 엘 그림은 도해·기호 설명·완전한 제목이 함께 보이도록 원문 영역 57개를 추가했다. 에스 그림 Ⅲ.1 흐름도도 추가했다. 기존 에스 그림 20개와 원래 이미지 340개는 유지한다.
- 엘 표 16(조작반/설계확인), 그림 Ⅷ.1(피트 사다리/레일 축), 그림 Ⅹ.2(두 로핑 예)는 원문에서 번호가 겹친다. 소속·제목·수록 위치로 구분하거나 선택 창을 보인다.
- 엘 부속서 Ⅻ의 본문은 `표 Ⅱ.1`을 참조하지만 이어지는 표제는 `표 Ⅻ.1`이다. 이 차이를 설명하며 실제 표에 연결하고 원문 문구는 유지한다.
- 현행 본문에 함께 남아 있는 옛 그림 제목은 제목까지 확인한다. 예: 에스 스커트 설명의 옛 `그림 1`을 현재의 스텝 시험 그림 1로 연결하지 않는다.
- KS B ISO 13857의 표 4를 엘 안전기준 표 4(진자충격시험)로 연결하지 않는다. 다른 별표·KS/EN 인용도 같은 원칙으로 구분한다.
- 표준화의 근거 인용에서 EN/KS/SPS 등 외부 규격으로 출처가 바뀌면, 다음 문단의 조문 번호도 그 출처를 유지한다. 별표22/24 표기가 다시 나오거나 다른 절로 바뀌면 출처를 갱신한다. 예: EN81-20의 5.12.3.2를 에스컬레이터 조문으로 연결하지 않는다.
- 적용 연혁은 해당 판의 이미지로 연결한다. 예: 옛 엘 그림 4는 178쪽, 옛 에스 그림 2는 66~67쪽이다. 현행 그림 번호로 대체하지 않는다.
- 표준화 자체 그림 1/2(균형추 칸막이, 급기댐퍼), 표 1/2(과속역행방지장치 시험하중) 등은 해당 안건의 실제 이미지를 쓴다.

## 재검사

최종 결과: 39개 검사 통과. 전체 카드·연혁에서 생성한 연결 6,459개, 원문 열람 대상 175개, 기존 이미지 파일 680개를 확인했다. 현행 내부 표·그림 참조의 미연결 항목은 0개다.

```bash
python -m unittest discover -s build/tests -v
```

원문 해시·검토한 쪽/영역/소속·예외 근거는 `reference_assets_map.json`에 있다. PDF가 바뀌면 해시 검사로 빌드를 중단하므로 새 판의 위치를 다시 확인해야 한다. 배포용 HTML은 `build.py`로 생성한다. 이번 전체 빌드에서 기존 본문·연혁 데이터와 이미지 340개가 이전 게시본과 동일함을 확인했다.

## 배포 파일·열어 둔 탭 재점검

사용자 화면과 결과가 다르다는 제보에 따라 테스트용 템플릿 재조립과 별개로, 저장소의 `index.html` 바이트를 그대로 제공하는 `test_published_page.py`를 추가했다. 테스트 훅이나 가상 카드를 삽입하지 않는다. 실제 목차 버튼 190개를 눌러 카드 2,461개와 본문 참조를 대조했으며 내부 표·그림의 연결 누락은 없었다. 부속서Ⅳ의 표Ⅱ.1 열기와, 저장된 열람 상태로 재접속했을 때도 표 3쪽이 로드됨을 확인했다.

수정 전 게시본 `4290f98`에서 해당 본문의 링크는 `3.1`뿐이다. 이 파일을 연 탭을 유지한 채 서버만 최신 파일로 교체하면 같은 표시가 남았으며, 페이지를 다시 불러오면 `표Ⅱ.1`, `3.1`, `3.6`이 모두 표로 연결됐다. 이 갱신 누락 경로는 재현했지만 사용자의 휴대폰에서 발생한 원인까지 확정한 것은 아니다.

`release.json`으로 게시 버전을 구분하고, 페이지 진입/복귀 시 최신 버전을 확인하도록 보완했다. 새 버전이면 버전이 붙은 주소로 다시 요청하면서 검색어·자료 필터·읽던 위치를 복원한다. 입력/팝업 사용 중에는 갱신을 미루고, 확인 요청이 지연되는 동안 팝업을 열어도 보호한다. 버전 확인이 실패해도 읽던 본문은 유지한다. 이 확인 코드가 없는 옛 탭은 한 번 최신 주소로 다시 열어야 한다.

검증 결과: 기존 회귀 검사 39개와 배포 원본/갱신 검사 7개를 모두 통과했다. 후자는 전체 목차 열람, 표 열기/재접속, 목차·검색 상태 갱신, 요청 실패, 팝업 사용 중 갱신 보류 및 지연 응답까지 포함한다.

이 실행 환경에서 실제 서비스 URL은 네트워크 정책의 403 응답으로 직접 대조하지 못했다. 위 검사는 배포 파일을 로컬 서버에 그대로 제공해 수행한 결과이며, GitHub Pages의 커밋별 배포 성공 여부는 별도로 확인한다.
